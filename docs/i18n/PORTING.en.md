## 1. Electron app structure

```
package.json            electron, vite, typescript, react, signalsmith-stretch, music-metadata, onnxruntime-node, electron-builder
src/main/               Electron main: window, menus (the Mac app's MyApp.swift menu layout), dialogs, autosave, recent files
src/core/               UI-independent TypeScript (must be testable in plain Node)
  models.ts             Models.swift (Clip, TransitionShape, TransitionLanes, AutoPoint, ClipEdit, CuePoint, TransitionTake, ClipPalette, ProjectFile…)
  tempo.ts              TempoFX.swift (TempoMap, OutroFX, FXKind, FXShape, ClipFX, FXState)
  automation.ts         Automation.swift
  layout.ts             MixStore.layout(), updateCutNudges(), suggestedMixOut() etc.
  project.ts            .djaw read/write (DJAWPACK)
  analysis/*.ts         AudioAnalyzer, StructureAnalyzer, LoudnessAnalyzer, NeuralAnalyzer (ONNX), AnalysisCache
  render/*.ts           Voice (read → stretch → EQ → FXKernel → echo → reverb → fader), RenderSession, WAV export, mix waveform
  i18n.ts               L(ja, en)
src/workers/            render.worker.ts (preview, export, waveform; Web Worker), analysis.child.ts (analysis; child process)
src/renderer/           React UI (store.ts = the UI-state part of MixStore, components/…)
src/vendor/stretch-core.mjs   generated by tools/signalsmith/make-core.mjs
tests/                  core tests (Node)
```

- `BrowserWindow` may use `nodeIntegration: true, contextIsolation: false, nodeIntegrationInWorker: true`
  (a personal app that only handles local files; using fs directly from the Worker is a big win).
- State: MixStore is "the document (clips, library, masterBPM, gridOffset…) + UI state".
  The document is updated with pure functions (`core/`), and Undo uses snapshots as in the Mac app (up to 300).
- IDs: Swift UUIDs are saved as upper-case strings → `crypto.randomUUID().toUpperCase()`.

## 2. Audio data

- **Decoding**: in the renderer, `OfflineAudioContext(2, 1, 44100).decodeAudioData(buf)` → everything ends up at 44.1 kHz.
  Chromium cannot read AIFF, so it is parsed by hand (header + big-endian PCM).
- **PCM cache**: `<userData>/cache/pcm/<fingerprint>.pcm` (16-bit stereo interleaved, length and sample rate in the header).
  Only the needed ranges are read, with `fs.readSync`. The track length comes from the source file's sample count / source sample rate (to match the Mac app's `duration`).
- **Fingerprint** (`AnalysisCache.fingerprint`): SHA-256 of (`"<size>"` + first 256 KB + last 256 KB if size > 512 KB), lower-case hex.
  The analysis, profile and stem caches are all keyed by it. It gives the same value as the Mac app, so `profiles` etc. in `.djaw` can be shared.
- **Metadata**: `music-metadata` (title, artist, artwork, genre tag).

## 3. The render engine (the most important part)

Read the Mac app's `MixRenderSession` / `PlaybackEngine.swift` / `DJFX.swift` / `StreamingPlayback.swift` / `OfflineRenderer.swift`.

### Units of time
- The timeline is in **reference seconds** (seconds at the base BPM = `masterBPM`). With tempo changes it differs from real time.
  Convert with `TempoMap.real(t)` and `reference(atReal:)`. Sample positions are always **real seconds × sample rate**.
- Playback rate of track `c`: `rate = master / c.bpm` (with `tempoSync`). Under a tempo map, `c.rate(tempo.bpm(at: t))`.
- The source ranges a track plays are given by `playSegments()` (including loops and jumps). `elapsed` is in source seconds.

### Steps
- One step per **512-frame boundary**, counted from the start of the mix. If a track starts in the middle of a step, the step is split there (`nextChunk`).
- At the centre time `t` of each step, `Automation.state(clips, i, t, master)` is evaluated and applied to every voice.
- Each track's voice starts **exactly** at the track's start frame (in the Mac app, voices that joined mid-way and drifted in the stretch unit caused long trouble).
  After the end, it keeps running for `tail = 8` seconds for echo and reverb tails.

### Inside a voice (Chain)
1. **Reading** (`ClipSchedule.ranges` / `BufferFeeder`): reads range by range.
   A **3 ms fade-in** at the head of the first range. When the next track is a `cut`, a **5 ms fade-out** at the end.
   Brake / backspin (`OutroFX`) replaces the ending with the result of `TurntableFX.render` (ported as is).
2. **Stretch / pitch**: signalsmith-stretch. `stretchRate` (exactly 1 becomes 1.00002 so it always processes).
   With key lock OFF (vinyl), transpose by `pitchCents`; key shift ±6 semitones.
   For each output block `inN = round(outN × rate)` (carry the remainder, so the accumulated error is zero).
   The latency (5292 samples in + out at 44.1 k) is **cancelled exactly**, e.g. by seeking with the input before the start position when the voice starts and discarding output.
   Test: pass a click train; the clicks in the output must be at `(input position − start position) / rate` within ±1 sample.
3. **EQ** (`DJEQ.configure`): low shelf 180 Hz / peaking 1 kHz, bandwidth 2 octaves / high shelf 4.5 kHz.
   Gains are `state.low/mid/high` (dB; kill is −40 dB, MID −24 dB). Biquads equivalent to Apple's AVAudioUnitEQ.
4. **DJ FX**: `FXKernel` (filter, phaser, flanger, bitcrusher, gate, roll) works per sample, so **port it as is**.
5. **Echo**: like AVAudioUnitDelay (delay = beat × 0.75 (echo-out) or `echoDiv`, feedback 55% (30 + 30 × amount for the FX),
   low-pass 7 kHz, wet/dry). For echo-out, `send` drops to 0 after 1 beat so only the tail remains.
6. **Reverb**: like AVAudioUnitReverb largeHall2 (something close such as Freeverb). wet = 55% × amount.
7. **Fader**: `state.volume` (gain × loudness correction × envelope).

- **Stems** (stage 3): the vocal and accompaniment reads are mixed before the stretch (`stemMix`).
- **Preview**: the same session renders 0.25 s ahead in the Worker and feeds the AudioWorklet.
  Changes to levels, EQ, FX and curves only are applied to the running session (`update`). Changes that move sounds (a different `structureKey`) rebuild it from the current position.
  The playhead comes from "frames the Worklet actually output", interpolated on screen to look smooth (the Mac app's `smoothPlayhead`).
- **Export**: WAV 24-bit and M4A (AAC 256 kbps), 44.1 k / 48 k. Normalising brings the peak to −1 dBFS (at most ×4 gain, `OfflineRenderer.normalizeGain`). The first pass measures the peak and the second writes (one pass is enough when the mix waveform's peak is available). The time left is estimated only once the stable phase starts.

## 4. The `.djaw` format (read and written by both Mac and Windows)

```
"DJAWPACK"            8 bytes
version               UInt32 LE (=1)
jsonLength            UInt64 LE
JSON                  ProjectFile (sorted keys, ISO 8601 dates)
audio files           the source files' bytes concatenated as is (media[].offset is relative to the end of the JSON)
```
- If it does not start with `DJAWPACK`, it is plain JSON (old format, autosave).
- `ProjectFile`: `format:"DJAW-Mix"`, `version:2`, `masterBPM`, `gridOffset`, `snap`, `clips`, `library`, `media`, `analyses`,
  `profiles`, `customTransitions`, `loudnessMode`, `ui`, `projectID`, `notes` etc. (end of `Models.swift`).
- `clips[].url` is a URL string like `file:///Users/...` (a Mac path). Resolution order when opening: embedded audio (`mediaID` → unpack folder) → `relativePath` (relative to the .djaw) → `url` → otherwise a "missing file" to relink.
  Windows paths are saved as `file:///C:/...`.
- Where embedded audio is unpacked: Mac `~/Library/Application Support/DJAW/Media/<projectID>/<mediaID>-<original file name>`, Windows `%APPDATA%/DJAW/Media/<projectID>/`.
- `analyses`: fingerprint → the Mac app's analysis (LZFSE-compressed binary plist). Windows need not read it (it re-analyses), but
  **keeps it unchanged when saving**, so opening on the Mac needs no re-analysis. The Windows analysis goes under another key (e.g. `analysesWin`).
- Real example: the user's `hyperflip.djaw` (about 400 MB, 9 embedded tracks, 5 in the mix + 4 in the library, masterBPM 107, tempo changes, custom lanes).

## 7. Pitfalls and history (what the Mac app taught us)

- **Export and preview matching**: the Mac app at first had a separate real-time path for preview, and track entries drifted from the export.
  In the end "render the preview with the same session as export and stream it". The Windows app does this from the start.
- **Stretch unit latency and speed drift**: voices joining mid-way came in late / early, and the gap between set and actual speed made beats drift (0.23 ms/s).
  Using signalsmith directly avoids both in principle, but always check with tests.
- **Cut-ins** (`updateCutNudges`): bar lines can be 10–40 ms away from the attack (kick / snare).
  The outgoing track stops just before the next attack, the incoming one starts just before its own attack (found with a 2 ms envelope, `BandEnergies.onsetOffset`).
  Keep only 5 ms of overlap: 5 ms fade-out on the outgoing side, 3 ms fade-in on the incoming side.
- **When automation is evaluated**: step boundaries count from the start of the mix (the same instants even when playing from the middle).
- **Levels just before a start**: for a track starting within 0.25 s, the value right after its start is set in advance (so the head of a cut-in is not lost).
- **Mix waveform**: loud tracks clip all the time and peaks alone draw a red band → draw peak + an RMS core.
  Redraw only the changed range with a 10 s run-up and reuse the rest shifted in time. After 20 s without edits, redraw everything exactly.
- **Timeline performance**: it got slow with many tracks → draw only the visible range, invalidate only the playhead strip while playing, cache the tempo map etc. per revision.
- **Colours**: neighbouring tracks are at least 0.15 apart in hue (`separateNeighbourColors`).
- **No duplicate loading**: judged by both the (normalised) path and the fingerprint. A track dropped on the timeline that is already in the library is moved from there into the mix.
- **Turntables**: a 60 Hz timer against the audio clock made them stutter → draw on every frame with an interpolated clock (corrects 15% of the error each time, re-syncs beyond 50 ms).
- **Auto VJ**: switched too often → switch per 8-bar phrase, at the head of drops, keeping each look for at least 2 phrases.
- **Export time left**: early estimates were unreliable → estimate only from progress in the stable phase, rounded to 5 s / 10 s.

## 9. Added in 0.4.0

- **Where a tempo change starts** (`Clip.tempoStart`): `'afterTransition'` (after the transition; the default for a new tempo change), `'mixIn'` or unset (with the transition; mixes from 0.3 and earlier), or a number (bars after the track comes in).
  The change starts at `timelineTimeOfBar(c, c.mixInBar + tempoStartBars(c))` and reaches the next BPM over `tempoRampBars(c)` bars (`Clip.tempoBars`, or the transition length when unset).
- **Layered tracks** (`ProjectFile.layers`, `Clip.layerOf`, `layerBar`, `layerParts`): pinned to a bar of a mix track (the host) and played on top of it.
  Positions come from `placeLayers` in `core/layers.ts`, deck C / D assignment from `layerDecks` (at most 2 at once).
  Rendering makes a one-track RenderSession per layered track and sums them in `renderNext()` (`nextChunk` is the minimum over all sessions).
  When `layerParts` is `vocals` / `instrumental`, stems are used and `Automation.state` mutes the other part.
- **Mixing out of a loop** (`Clip.outPass`): when the previous track loops, on which pass the transition happens. Applied in the layout through `elapsedOfSourcePass`.
- **Languages**: tables keyed by the English text of `L(ja, en)` (`src/core/locales/<lang>.json`). For calls whose English is a template string, `scripts/i18n.mjs` adds the key and values at build time.
  Saved text such as auto-mix notes is made with `captureLanguages()`, which keeps markers for every language, and `localize()` shows it in the current language.
  Extract keys with `node scripts/i18n.mjs extract`, join translations with `node scripts/i18n-merge.mjs` (`_parts/c<N>_*.json`, 200 per part).
- **File size**: embedded uncompressed audio (WAV) is stored as FLAC (`core/flac.ts`, fixed predictors + Rice coding, bit-identical to the source). MP3 and the like are kept as they are.
