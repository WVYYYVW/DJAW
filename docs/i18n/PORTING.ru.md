## 1. Устройство приложения Electron

```
package.json            electron, vite, typescript, react, signalsmith-stretch, music-metadata, onnxruntime-node, electron-builder
src/main/               Electron main: окно, меню (структура меню MyApp.swift на Mac), диалоги, автосохранение, недавние файлы
src/core/               TypeScript без зависимости от UI (должен тестироваться в одном Node)
  models.ts             Models.swift (Clip, TransitionShape, TransitionLanes, AutoPoint, ClipEdit, CuePoint, TransitionTake, ClipPalette, ProjectFile…)
  tempo.ts              TempoFX.swift (TempoMap, OutroFX, FXKind, FXShape, ClipFX, FXState)
  automation.ts         Automation.swift
  layout.ts             MixStore.layout(), updateCutNudges(), suggestedMixOut() и т. д.
  project.ts            чтение/запись .djaw (DJAWPACK)
  analysis/*.ts         AudioAnalyzer, StructureAnalyzer, LoudnessAnalyzer, NeuralAnalyzer (ONNX), AnalysisCache
  render/*.ts           Voice (чтение → растяжение → EQ → FXKernel → эхо → реверберация → фейдер), RenderSession, экспорт WAV, волна микса
  i18n.ts               L(ja, en)
src/workers/            render.worker.ts (предпрослушивание, экспорт, волна; Web Worker), analysis.child.ts (анализ; дочерний процесс)
src/renderer/           UI на React (store.ts = часть MixStore с состоянием UI, components/…)
src/vendor/stretch-core.mjs   генерируется tools/signalsmith/make-core.mjs
tests/                  тесты core (Node)
```

- В `BrowserWindow` можно `nodeIntegration: true, contextIsolation: false, nodeIntegrationInWorker: true`
  (личное приложение, работающее только с локальными файлами; прямой доступ к fs из Worker — большой плюс).
- Состояние: MixStore — это «документ (clips, library, masterBPM, gridOffset…) + состояние UI».
  Документ меняется чистыми функциями (`core/`), отмена работает на снимках, как на Mac (до 300).
- ID: UUID из Swift сохраняются строками в верхнем регистре → `crypto.randomUUID().toUpperCase()`.

## 2. Аудиоданные

- **Декодирование**: в renderer `OfflineAudioContext(2, 1, 44100).decodeAudioData(buf)` → всё приводится к 44,1 кГц.
  Chromium не читает AIFF, поэтому он разбирается вручную (заголовок + PCM big-endian).
- **Кэш PCM**: `<userData>/cache/pcm/<отпечаток>.pcm` (16 бит, стерео, чередование; длина и частота дискретизации в заголовке).
  Читаются только нужные участки через `fs.readSync`. Длина трека берётся из числа сэмплов / частоты исходного файла (чтобы совпадать с `duration` на Mac).
- **Отпечаток** (`AnalysisCache.fingerprint`): SHA-256 от (`"<размер>"` + первые 256 КБ + последние 256 КБ, если размер > 512 КБ), шестнадцатеричный в нижнем регистре.
  Кэши анализа, профилей и стемов используют его как ключ. Значение совпадает с Mac, поэтому `profiles` и др. в `.djaw` общие.
- **Метаданные**: `music-metadata` (название, исполнитель, обложка, жанровый тег).

## 3. Движок рендеринга (самое важное)

Прочитайте `MixRenderSession` / `PlaybackEngine.swift` / `DJFX.swift` / `StreamingPlayback.swift` / `OfflineRenderer.swift` из версии для Mac.

### Единицы времени
- Таймлайн измеряется в **опорных секундах** (секунды при базовом BPM = `masterBPM`). При сменах темпа оно расходится с реальным временем.
  Перевод — `TempoMap.real(t)` и `reference(atReal:)`. Позиции сэмплов всегда **реальные секунды × частота дискретизации**.
- Скорость трека `c`: `rate = master / c.bpm` (при `tempoSync`). При карте темпа — `c.rate(tempo.bpm(at: t))`.
- Участки исходника, которые играет трек, даёт `playSegments()` (с лупами и прыжками). `elapsed` — в секундах исходника.

### Шаги
- Один шаг на каждую **границу 512 кадров**, считая от начала микса. Если трек начинается посреди шага, шаг делится в этом месте (`nextChunk`).
- В середине каждого шага, в момент `t`, вычисляется `Automation.state(clips, i, t, master)` и применяется ко всем голосам.
- Голос каждого трека стартует **ровно** с его начального кадра (на Mac голоса, подключавшиеся посередине и съезжавшие в блоке растяжения, долго доставляли проблемы).
  После конца он работает ещё `tail = 8` секунд ради хвостов эха и реверберации.

### Внутри голоса (Chain)
1. **Чтение** (`ClipSchedule.ranges` / `BufferFeeder`): участок за участком.
   **Появление 3 мс** в начале первого участка. Если следующий трек — `cut`, **затухание 5 мс** в конце.
   Торможение / бэкспин (`OutroFX`) заменяет концовку результатом `TurntableFX.render` (перенесено как есть).
2. **Растяжение / высота**: signalsmith-stretch. `stretchRate` (ровно 1 превращается в 1,00002, чтобы обработка шла всегда).
   При выключенном key lock (винил) транспонировать на `pitchCents`; сдвиг тональности ±6 полутонов.
   Для каждого выходного блока `inN = round(outN × rate)` (остаток переносится — накопленная ошибка нулевая).
   Задержка (5292 сэмпла вход + выход при 44,1 к) **точно компенсируется**, например перемоткой с входом до начальной позиции при старте голоса и отбрасыванием выхода.
   Тест: пропустить серию щелчков; щелчки на выходе должны быть в `(позиция на входе − начальная позиция) / rate` с точностью ±1 сэмпл.
3. **EQ** (`DJEQ.configure`): низкая полка 180 Гц / колокол 1 кГц, ширина 2 октавы / высокая полка 4,5 кГц.
   Усиления `state.low/mid/high` (дБ; kill −40 дБ, MID −24 дБ). Биквады, эквивалентные AVAudioUnitEQ от Apple.
4. **DJ FX**: `FXKernel` (фильтр, фэйзер, флэнжер, биткрашер, гейт, ролл) работает по сэмплам, поэтому **переносится как есть**.
5. **Эхо**: как AVAudioUnitDelay (задержка = доля × 0,75 (уход в эхо) или `echoDiv`, обратная связь 55% (как FX — 30 + 30 × сила),
   ФНЧ 7 кГц, wet/dry). При уходе в эхо `send` через 1 долю падает до 0, остаётся только хвост.
6. **Реверберация**: как largeHall2 у AVAudioUnitReverb (что-то близкое, например Freeverb). wet = 55% × сила.
7. **Фейдер**: `state.volume` (усиление × коррекция громкости × огибающая).

- **Стемы** (этап 3): чтения вокала и аккомпанемента смешиваются до растяжения (`stemMix`).
- **Предпрослушивание**: та же сессия в Worker рендерит на 0,25 с вперёд и передаёт в AudioWorklet.
  Изменения только уровней, EQ, FX и кривых применяются к работающей сессии (`update`). Изменения, сдвигающие звуки (меняется `structureKey`), пересоздают её с текущей позиции.
  Положение курсора берётся из «кадров, реально выданных Worklet», и интерполируется на экране для плавности (`smoothPlayhead` на Mac).
- **Экспорт**: WAV 24 бит и M4A (AAC 256 кбит/с), 44,1 к / 48 к. Нормализация выводит пик на −1 dBFS (усиление не больше ×4, `OfflineRenderer.normalizeGain`). Первый проход меряет пик, второй пишет (хватает одного, если известен пик волны микса). Оставшееся время оценивается только после начала стабильной фазы.

## 4. Формат `.djaw` (читается и пишется на Mac и Windows)

```
"DJAWPACK"            8 bytes
version               UInt32 LE (=1)
jsonLength            UInt64 LE
JSON                  ProjectFile (ключи отсортированы, даты ISO 8601)
аудиофайлы            байты исходных файлов, склеенные как есть (media[].offset отсчитывается от конца JSON)
```
- Если файл начинается не с `DJAWPACK`, это обычный JSON (старый формат, автосохранение).
- `ProjectFile`: `format:"DJAW-Mix"`, `version:2`, `masterBPM`, `gridOffset`, `snap`, `clips`, `library`, `media`, `analyses`,
  `profiles`, `customTransitions`, `loudnessMode`, `ui`, `projectID`, `notes` и др. (конец `Models.swift`).
- `clips[].url` — строка URL вида `file:///Users/...` (путь на Mac). Порядок поиска при открытии: встроенный звук (`mediaID` → папка распаковки) → `relativePath` (относительно .djaw) → `url` → иначе «файл не найден» с предложением перепривязать.
  Пути Windows сохраняются как `file:///C:/...`.
- Куда распаковывается встроенный звук: Mac `~/Library/Application Support/DJAW/Media/<projectID>/<mediaID>-<исходное имя>`, Windows `%APPDATA%/DJAW/Media/<projectID>/`.
- `analyses`: отпечаток → анализ версии для Mac (бинарный plist, сжатый LZFSE). Windows может его не читать (анализирует заново), но
  **сохраняет нетронутым**, чтобы при открытии на Mac не требовался повторный анализ. Анализ Windows хранится под другим ключом (например, `analysesWin`).
- Реальный пример: `hyperflip.djaw` пользователя (около 400 МБ, 9 встроенных треков, 5 в миксе + 4 в библиотеке, masterBPM 107, смены темпа, собственные дорожки).

## 7. Подводные камни и история (чему научила версия для Mac)

- **Совпадение экспорта и предпрослушивания**: сначала на Mac был отдельный путь реального времени для предпрослушивания, и входы треков расходились с экспортом.
  В итоге: «рендерить предпрослушивание той же сессией, что и экспорт, и воспроизводить». Версия для Windows так устроена с самого начала.
- **Задержка и дрейф скорости блока растяжения**: голоса, подключавшиеся посередине, входили поздно / рано, а расхождение заданной и реальной скорости уводило доли (0,23 мс/с).
  При прямом использовании signalsmith ни того, ни другого в принципе нет, но обязательно проверять тестами.
- **Склейки** (`updateCutNudges`): тактовые линии могут отстоять от атаки (бочка / малый) на 10–40 мс.
  Уходящий трек останавливается прямо перед следующей атакой, входящий начинается прямо перед своей (ищется огибающей 2 мс, `BandEnergies.onsetOffset`).
  Перекрытие только 5 мс: затухание 5 мс у уходящего, появление 3 мс у входящего.
- **Когда вычисляется автоматизация**: границы шагов отсчитываются от начала микса (те же моменты, даже если играть с середины).
- **Уровни прямо перед стартом**: для трека, стартующего менее чем через 0,25 с, значение сразу после старта выставляется заранее (чтобы не потерять начало склейки).
- **Волна микса**: громкие треки постоянно клиппуют, и одни пики дают красную полосу → рисовать пик + ядро RMS.
  Перерисовывать только изменённый участок с разгоном 10 с, остальное переиспользовать со сдвигом по времени. После 20 с без правок перерисовать всё точно.
- **Тяжесть таймлайна**: тормозил при большом числе треков → рисовать только видимое, при воспроизведении инвалидировать только полосу курсора, кэшировать карту темпа и пр. по ревизиям.
- **Цвета**: соседние треки отстоят по тону минимум на 0,15 (`separateNeighbourColors`).
- **Без повторной загрузки**: проверка и по (нормализованному) пути, и по отпечатку. Трек, брошенный на таймлайн и уже лежащий в библиотеке, переносится оттуда в микс.
- **Вертушки**: таймер 60 Гц против аудиочасов давал рывки → рисовать каждый кадр по интерполированным часам (исправляет 15% ошибки за раз, пересинхронизация при расхождении больше 50 мс).
- **Авто-VJ**: переключался слишком часто → переключать по 8-тактовым фразам, в начале дропов, держать каждую картинку минимум 2 фразы.
- **Оставшееся время экспорта**: первые оценки были ненадёжны → оценивать только по ходу стабильной фазы, округляя до 5 с / 10 с.

## 9. Добавлено в 0.4.0

- **Где начинается смена темпа** (`Clip.tempoStart`): `'afterTransition'` (после перехода; по умолчанию для новой смены темпа), `'mixIn'` или не задано (вместе с переходом; миксы 0.3 и раньше) или число (тактов после входа трека).
  Смена начинается в `timelineTimeOfBar(c, c.mixInBar + tempoStartBars(c))` и доходит до следующего BPM за `tempoRampBars(c)` тактов (`Clip.tempoBars`, а если не задано — длина перехода).
- **Наложенные треки** (`ProjectFile.layers`, `Clip.layerOf`, `layerBar`, `layerParts`): привязаны к такту трека микса (хозяина) и играют поверх него.
  Позиции даёт `placeLayers` из `core/layers.ts`, распределение по декам C / D — `layerDecks` (одновременно не более 2).
  При рендере на каждый наложенный трек создаётся RenderSession с одним треком, и `renderNext()` их суммирует (`nextChunk` — минимум по всем сессиям).
  Если `layerParts` равно `vocals` / `instrumental`, используются стемы, и `Automation.state` глушит другую часть.
- **Выход из лупа сведением** (`Clip.outPass`): если предыдущий трек в лупе — на каком проходе происходит переход. Учитывается в раскладке через `elapsedOfSourcePass`.
- **Языки**: таблицы с английским текстом из `L(ja, en)` в качестве ключа (`src/core/locales/<lang>.json`). Для вызовов, где английский — шаблонная строка, `scripts/i18n.mjs` при сборке добавляет ключ и значения.
  Сохраняемые тексты, например заметки автосведения, создаются через `captureLanguages()`, который хранит метки для всех языков, а `localize()` показывает их на текущем языке.
  Извлечение ключей: `node scripts/i18n.mjs extract`; сборка переводов: `node scripts/i18n-merge.mjs` (`_parts/c<N>_*.json`, по 200).
- **Размер файла**: встроенный несжатый звук (WAV) хранится во FLAC (`core/flac.ts`, фиксированные предикторы + коды Райса, побитово совпадает с исходником). MP3 и подобные остаются как есть.
